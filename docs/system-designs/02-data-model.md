# Current data model

Material Derailleur / BWorks · October 19, 2026 · Repository snapshot `3c75abdc`

Six entities from the current Prisma schema. Representative fields show keys, item ownership, optional program assignment and reviewable history.

```mermaid

    Program |o..o{ DonatedItem : groups
    DonatedItem ||..o{ DonatedItemStatus : has_history
    DonatedItem ||..o{ ItemAttribute : has_attributes

    Donor {
        Int id PK
        String email UK
        String firstName
        String lastName
        String zipcode
        Boolean emailOptIn
    }

    Program {
        Int id PK
        String name
        String description
        DateTime startDate "PostgreSQL DATE"
        String aimAndCause
    }

    DonatedItem {
        Int id PK
        Int donorId FK "required"
        Int programId FK "nullable"
        String itemType
        String category
        Int quantity
        String currentStatus
        DateTime dateDonated
        DateTime lastUpdated
        String imagePath "nullable"
        Json analysisMetadata "nullable AI metadata"
    }

    DonatedItemStatus {
        Int id PK
        Int donatedItemId FK "required; cascade on item deletion"
        String statusType
        DateTime dateModified
        String[] imageUrls
        Boolean approval "false by default"
        Boolean donorInformed "notification request; not delivery proof"
        String submitter
    }

    ItemAttribute {
        Int id PK
        Int donatedItemId FK "required; cascade on item deletion"
        String descriptor
        String stringValue "nullable"
        Float numberValue "nullable"
        Boolean booleanValue "nullable"
    }

    User {
        String id PK "UUID generated by default"
        String email UK
        String name
        String password "stored hash"
        Role role "nullable"
        UserStatus status "PENDING by default"
        Boolean firstLogin
        String resetToken "nullable"
        DateTime resetTokenExpiry "nullable"
    }
```

Each item has exactly one donor and zero or one program. Donors and programs may have no items. Each status or attribute belongs to exactly one item; an item may have zero or many of each. Dashed associations mean the child has its own primary key; `PK`, `FK` and `UK` mean primary, foreign and unique key. Deleting an item cascades to its status and attribute rows.

`User` and `Donor` have **no foreign key relationship**. The donor profile endpoint matches their email addresses in application code. `nullable` represents Prisma's `?`; the schema does not enforce exactly one populated value column per `ItemAttribute`. Account roles are ADMIN, DONOR, TIER_ONE, TIER_TWO and TIER_THREE; account statuses are PENDING, ACTIVE and SUSPENDED. Item status labels are strings, separate from account status and review approval.
